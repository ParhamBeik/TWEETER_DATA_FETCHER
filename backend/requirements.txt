# Pinned with ~=, which allows the patch series and nothing else
# (`Django~=5.2.17` accepts 5.2.18, never 5.3).
#
# Open `>=` ranges were not a policy, they were a liability: the image is rebuilt
# from this file on every deploy, so a fresh build silently resolved gunicorn 26,
# pytest 9, redis 8 and rich 15 -- majors nobody had run the suite against -- and
# two builds of the same commit could ship different dependency sets. A green CI
# run said nothing about the image that followed it. The patch series is the
# widest range that still carries security fixes without carrying behaviour
# changes.
#
# To move one: raise the pin, run `python -m pytest` (and CI, which runs the same
# suite against Postgres), then commit the pin with the evidence.
# Verified together on Python 3.11 against SQLite and PostgreSQL: 443 passed.

# Django 5.2 is the LTS (supported to April 2028). The previous `<5.2` ceiling
# held this project on 5.1, which reached end of life in December 2025 -- no
# security fixes at all.
